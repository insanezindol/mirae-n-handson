# RCA 리포트 마스킹 규칙

리포트는 회고 자리와 저장소에서 여러 사람이 읽는다. 원본 로그의 식별 정보가 리포트로 옮겨 가지 않게, `docs/rca/` 에 쓰는 모든 내용에 아래 규칙을 적용한다. 본문 · 표 · 원문 발췌 · 실행 기록의 명령과 출력이 모두 대상이다.

## 바꾸는 값

| 대상 | 원본의 모양 | 리포트에 쓰는 값 |
|---|---|---|
| IP 주소 | `10.20.6.87` | `10.20.x.x` (앞 두 자리만 남긴다) |
| 구분이 필요한 IP | upstream 서버, 특정 클라이언트 | 역할 별칭: `API-1`, `API-2`, `교사단말A`, `교사단말B` … |
| 이메일 | `이름@도메인` | `[EMAIL]` |
| 학생 식별자 | `STU-<숫자>` | `학생A`, `학생B` … (등장 순서대로) |
| 토큰 · Authorization 값 | `Bearer eyJ…`, API 키, 세션 ID | `[TOKEN]` |
| 비밀번호 · 접속 문자열 | `-p<비밀번호>`, `password=…`, `jdbc:…//사용자:비밀번호@…` | `[SECRET]` |

## 적용 방법

- IP 는 기본이 `10.20.x.x` 다. 같은 IP 를 여러 번 가리켜 서로 구분해야 분석이 읽힐 때만 역할 별칭을 쓴다(예: "어느 서버가 제외됐는가", "어느 단말이 반복 요청했는가").
- 별칭은 역할 + 순번으로 짓고, 리포트 한 편 안에서 같은 값에는 같은 별칭을 쓴다. 호스트명이나 사람 이름에서 따오지 않는다.
- 별칭과 원래 값의 대응은 작업 중에만 기억한다. 표나 파일로 남기지 않는다. 대응표가 남으면 마스킹이 되돌려진다.
- 쿼리 문자열에 식별자가 든 URL 은 집계할 때 쿼리 문자열을 잘라 낸다(`sub(/\?.*/,"",$7)`). 발췌에 꼭 필요하면 값만 별칭으로 바꾼다.
- 실행 기록의 명령에 든 IP 도 별칭으로 바꾼다. 그 절 첫머리에 "명령 안의 값이 별칭으로 바뀌어 있어, 다시 실행하려면 원본 로그의 값을 넣어야 한다"고 적는다.
- 민감 값이 든 줄을 발견했다는 사실 자체는 `파일:줄번호` 로 리포트에 적는다(예: 로그에 토큰이 찍힌다). 값은 옮기지 않는다.
- 가리지 않는 것: 더미 도메인(`example.com`), 학급 · 배포 · 문항의 숫자 ID, 단원 코드, 커넥션 객체 ID, 스레드 이름.

## 저장 뒤 검사

`F=docs/rca/<시나리오>.md` 로 두고 실행한다. 세 명령 모두 출력이 없어야 한다.

```bash
grep -nE '([0-9]{1,3}\.){3}[0-9]{1,3}' "$F"                      # IP
grep -nE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}' "$F"       # 이메일
grep -nE 'STU-[0-9]+|Bearer +[A-Za-z0-9]|eyJ[A-Za-z0-9_-]{8,}' "$F"   # 학생 식별자 · 토큰
```

- 걸린 줄이 버전 번호처럼 민감 값이 아니면 그대로 둔다. 그 밖에는 고친 뒤 다시 검사한다.
- 비밀번호는 모양이 일정하지 않아 명령으로 다 잡히지 않는다. 리포트에 적은 명령 · 설정 인용을 눈으로 다시 본다.

## 리포트 마지막 줄

적용한 건수를 종류별로 적는다. 0건도 적는다.

```
마스킹 적용: IP 주소 82건 · 이메일 0건 · 학생 식별자 3건 · 토큰 · Authorization 값 2건 · 비밀번호 · 접속 문자열 1건
```
