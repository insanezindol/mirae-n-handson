# 변경 영향도 분석

## 원칙
- 코드를 고치지 않는다. 파일을 만들거나 수정하지 않고, 결과는 답변으로만 보고한다.
- 모든 항목에 근거 `파일:줄번호` 를 단다. 경로는 저장소 루트 기준 상대 경로로 적는다(`legacy/item-bank-php/search.php:586`).
- 근거는 실행되는 코드여야 한다. 주석 · 문서의 설명만으로는 호출 관계나 테이블 사용을 단정하지 않는다.
- 실제 호출문으로 확인하지 못한 경로는 호출 경로에 넣지 않고 "추적 한계"에 적는다. 있을 법한 호출을 지어내지 않는다.

## 1. 대상 정하기
- `$ARGUMENTS` 가 `파일:줄번호` 면 그 줄을 감싸는 함수 · 메서드 · 프로시저를 대상으로 한다.
- 이름이면 Grep 으로 정의를 찾는다.
  - PHP `function <이름>` · Java 메서드 선언 · SQL `CREATE (OR ALTER) PROCEDURE <이름>` · TS `function <이름>` / `const <이름> =`.
  - 저장 프로시저는 `db/mssql/init/04-procs.sql` 과 `legacy/grade-mssql/sql/` 두 곳에 정의가 있을 수 있다. 둘 다 있으면 둘 다 적고, 내용이 다르면 차이를 보고에 적는다.
- 정의가 여러 개(같은 이름 · 오버로드 · 다른 모듈)면 후보를 `파일:줄번호` 로 나열하고 어느 것인지 사람에게 묻는다. 정의가 없으면 "정의를 찾지 못함"과 검색한 패턴을 적고 멈춘다.
- 인자가 없으면 무엇을 분석할지 묻는다.

## 2. 호출부 역추적 (대상 → 진입점)
- 대상 이름으로 저장소 전체를 Grep 해 직접 호출부를 찾는다. `legacy/*/vendor/` · `node_modules/` · 빌드 산출물은 뺀다.
- 찾은 호출부마다 그 줄을 감싸는 함수를 확인하고, 그 함수 이름으로 다시 호출부를 찾는다. 진입점에 닿을 때까지 반복한다.
- 진입점으로 보는 것:

| 대상 | 진입점 | 확인할 것 |
|---|---|---|
| PHP (`legacy/item-bank-php`) | 브라우저가 직접 여는 최상위 `.php` 파일 | `require` · `include` 로 끌려오는 `inc/` 파일은 진입점이 아니다. 그 파일을 require 하는 최상위 파일까지 올라간다 |
| Spring MVC (`legacy/assignment-thymeleaf`, `legacy/grade-mssql`) | `@GetMapping` · `@PostMapping` 등이 붙은 Controller 메서드(URL) | 클래스의 `@RequestMapping` 경로와 합친 URL, 반환하는 템플릿 이름(화면) |
| Thymeleaf 화면 | `templates/*.html` 의 `th:action` · `th:href` | 그 URL 로 요청을 보내는 화면을 "영향받는 화면"에 넣는다 |
| 저장 프로시저 | 프로시저를 `EXEC` 하는 Java · SQL 코드 → 그 코드의 Controller | 다른 프로시저 안의 `EXEC` 도 호출부다 |
| modern/api | `@RestController` 메서드(URL) | modern/web 에서 그 URL 을 부르는 `src/api/*.ts` → 훅 → 컴포넌트까지 |

- 호출 경로는 `진입점 → … → 대상` 한 줄로 적고, 단계마다 호출문이 있는 `파일:줄번호` 를 붙인다. 경로가 갈라지면 경로마다 한 줄씩 적는다.
- 같은 단계를 두 번 만나면(재귀 · 순환) 그 자리에서 멈추고 "순환"이라고 적는다.

## 3. 테이블 영향
- 대상 함수 본문(그리고 대상이 부르는 하위 함수 · 프로시저)의 SQL 에서 읽고 쓰는 테이블 · 뷰를 찾는다. SELECT / INSERT / UPDATE / DELETE / MERGE 를 구분한다.
- 뷰를 쓰면 뷰 정의(`db/mariadb/init/01-schema.sql`, `db/mssql/init/01-schema.sql`)를 읽어 실제 테이블까지 풀어 적는다. 트리거 · 외래 키의 `ON DELETE` / `ON UPDATE` 로 번지는 테이블도 스키마에서 확인한다.
- 찾은 테이블마다 같은 테이블을 읽거나 쓰는 다른 함수 · 프로시저 · 뷰를 저장소 전체(`legacy/`, `modern/`, `db/`)에서 Grep 한다. JPA 엔티티는 `@Table(name = …)` · 클래스 이름으로 매핑을 확인한다.
- `docs/<모듈명>/ERD.md` 가 있으면 테이블별 읽기/쓰기 위치 표와 대조하고, 표에 없는 위치를 찾으면 따로 적는다.

## 4. 관련 규칙 ID
- 대상이 속한 모듈의 `docs/<모듈명>/BUSINESS-RULES.md` 가 있으면 읽는다. 모듈명은 아래 표로 정한다.

| 경로 | 모듈명 |
|---|---|
| `legacy/item-bank-php` | `item-bank` |
| `legacy/assignment-thymeleaf` | `assignment` |
| `legacy/grade-mssql` | `grade` |

- 규칙의 근거 줄이 대상 함수 본문 범위 안에 있거나, 대상이 쓰는 테이블 · 뷰를 근거로 하는 규칙을 연결한다. 규칙 ID 와 연결 이유(겹치는 근거 줄)를 적는다.
- 문서가 없으면 "BUSINESS-RULES.md 없음"이라고 적고 넘어간다. 문서를 새로 만들지 않는다.

## 5. 추적 한계
검색으로 호출 관계를 확정할 수 없는 곳은 호출 경로에 섞지 않고 "추적 한계"에 모은다. 적어도 아래를 찾아본다.
- PHP: `call_user_func` · `call_user_func_array`, 변수 함수 `$fn(...)`, `$obj->$method(...)`, 문자열로 만든 `include` 경로.
- Java: 리플렉션(`Method.invoke`, `Class.forName`), 인터페이스 · 상속으로 구현체가 여러 개인 호출, AOP · 이벤트 리스너, `@Scheduled`.
- SQL: 동적 SQL(`sp_executesql`, `EXEC(@sql)`, 문자열로 이어 붙인 쿼리), 트리거, DB 밖(배치 · 외부 시스템)에서 부르는 프로시저.
- 템플릿 · 프론트: 문자열 조합으로 만든 URL, 조건부 렌더링.
- 스킬이 볼 수 없는 것: 운영 DB 에만 있는 객체, 다른 저장소 · 스케줄러에서 오는 호출.

각 항목에 의심 근거 줄과 "무엇을 확인하면 확정되는지"를 적는다.

## 6. 출력 형식 (순서 고정)

### 대상
- `이름` — 정의 `파일:줄번호`(줄 범위), 한 줄 설명

### 1) 영향받는 화면
| 화면 · URL | 진입점 파일:줄번호 | 영향 이유 |
|---|---|---|

### 2) 호출 경로
- `<진입점>` (화면 · URL, `파일:줄번호`) → `<중간 함수>` (호출문 `파일:줄번호`) → **대상** (호출문 `파일:줄번호`)

### 3) 영향받는 테이블
| 테이블 · 뷰 | 대상의 접근 | 근거 | 같은 테이블을 쓰는 다른 함수 (접근 · 근거) |
|---|---|---|---|

### 4) 관련 규칙 ID
| 규칙 ID | 규칙 요약 | 연결 이유 · 근거 |
|---|---|---|

### 5) 수정 전에 확보해야 할 테스트 케이스
| # | 케이스(입력 → 기대 결과) | 지키려는 것(규칙 ID · 호출 경로 · 테이블) | 있는 테스트 / 없음 |
|---|---|---|---|

- 현재 동작을 고정하는 특성화 테스트를 먼저 제안한다. 경계값 · 빈 값 · 예외 분기를 포함한다.
- `characterization/` · `modern/*/src/test` 에 이미 같은 동작을 다루는 테스트가 있으면 그 `파일:줄번호` 를 적는다.

### 6) 추적 한계
| 의심 위치 | 이유 | 확인 방법 |
|---|---|---|

- 없으면 "찾은 추적 한계 없음(검색한 패턴: …)"을 적는다.
- 해당 항목이 비면 표 대신 "없음"과 이유를 한 줄로 적는다.
